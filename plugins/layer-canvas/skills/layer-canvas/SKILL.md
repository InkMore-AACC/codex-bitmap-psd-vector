# 分层画布

这是 Windows 本地 Codex 插件。全程使用打开画布的当前真实任务 ID。所有模型推理、生图和修改留在当前对话，不能新建/分叉 Codex 任务或另起 `codex exec` 推理进程完成请求。不要通过独立 API 调用 OpenAI 来代替当前对话额度。

## 打开、导入与当前任务

1. 从当前执行上下文或环境 `CODEX_THREAD_ID` 确认真实任务 ID。没有证据时不要猜 ID。调用 `canvas_open(taskId)`，再用 Codex `open_in_codex` 把返回的完整 URL 放到当前任务右侧。
2. 用户要求把当前图片放进画布时，使用实际生成工具返回的原文件绝对路径调用 `canvas_import`。可上传 PNG/JPEG/WebP/PSD/SVG。缺少原图时不能用聊天截图代替。多张图片分别导入，保留各自身份。
3. 工具里的 `taskId` 必须是当前任务；不得复制旧任务 URL。图层与标注坐标使用输入图片像素，与浏览器缩放和画布坐标不同。箭尾和文字允许在图外，箭头末端是目标。领取包 coordinateAnnotations 给出图片/图层 ID、点、框、笔刷轨迹和独立黑白选区 maskPath；sourcePath 是干净输入，originalSourcePath 是沿来源链找到的最初原图（只读辅助参考，可能来自已删除节点的素材存档）。当前节点、已确认修改和本次意见优先，不得因原图差异撤回已确认修改。originalReference.complete=false 表示来源链不完整，不得声称已找到最初原图。只读取参考，不执行任何上游任务。不要将画布带标注截图传给生图代替原图；实际工具不支持蒙版参数时只能作为位置提示，不能声称硬约束。

## 接收画布请求

画布按钮保存冻结请求后，通过已安装的官方 Codex App Tools MCP 的 `send_message_to_thread` 自动发送到该画布绑定的当前对话。无需用户开启接单、手动发“处理画布请求”或让对话常驻轮询。此发送保持原对话及其模型设置，不使用独立推理会话。

收到自动消息时，只读取并处理消息里的精确 jobId。先核实 taskId 与当前真实对话一致；请求已取消、完成或失败则停止，已被领取的请求不要重复领取。`canvas_wait_requests` 仅用于用户明确要求批量处理或等待，普通打开画布不应无限占用对话。发送回执只表示送达，不表示实际执行或生成完成。发送失败由画布显示可理解的原因，不要让用户手动接单掩盖故障。

桌面连接由 `canvas_open` 自动刷新，只使用官方 MCP 服务及宿主传入的连接环境。不写 Codex 私有数据库，不调用私有桌面协议，不用独立 CLI 队列冒充桌面对话唤醒。历史未发送任务不会在升级或重启后自动执行。

插件连接加载时自动启动网页服务；关联 Codex 宿主全部退出后，等本地队列和请求完成，再空闲约15–20秒停止。关闭标签不停止其他画布；不自动加载抠图模型。`canvas_open` 仍负责当前对话绑定、刷新发送连接及按需启动备用。若恢复标签显示浏览器自身的无法访问页，可刷新或重新打开；不得用空白新文档覆盖历史。

每次仅处理请求 imageId 对应节点。父子连线只表示来源，不是执行链；不得自动处理上下游节点的分层、矢量化或修改，也不得自动从预分层继续生成或矢量化。正式完成产物创建关联新节点。

领取包包含冻结的 `taskId / documentId / imageId / version`、原图、图层、本地素材、总图意见、逐层意见、标注和请求类型。先看实际干净原图及有关已完成图层，预览层只读取结构化标注，不能只读文字猜图。保留这些 IDs 和输入版本直至回传；切换当前选中图片不能改变请求归属。

## 默认重建与补图一致性

真实生图前须将prepare第一张干净参考与整图同坐标局部对照；规划框漏掉源中可见笔画/轮廓时，保留未调用请求、记录参考失败，不把截笔当成原图固有边缘。新v4 normal透明前景可按RECONSTRUCTION.md显式使用referenceContext补充干净周边与本次carrier，不能追改冻结frame、定位点或旧prepared。循环每轮用针对上一轮失败的全新复杂海报；同轮图层候选不是新轮次，某层失败后继续其他相关组及组合验证。技术或局部通过不代表普通与PS整体验收。

每次调用 Codex 生图/编辑，以及 PS/AI 重建时，必须把任务包 `referencePolicy` 的原则与本次意见一起传入实际执行提示词，不能只在规划阶段提及。原图指来源链中最初导入的干净图片 `originalSourcePath`，先查看实际原图、当前节点及有关图层；未被明确修改的内容以最初原图为视觉一致性基准，当前节点及已确认修改为工作基准，本次明确要求优先。禁止为贴回原图撤销已确认修改，也不能把中间失真当成用户设计意图。

默认保持主体、构图、形状、位置比例、透视、材质、光照、色彩、文字外观、阴影及透明细节。特殊要求只覆盖其图层或标注作用域，其余保持一致。粗抠和精抠只有用户预览清晰度不同，最终重建流程一致。任务包预览层只有名称、归属、坐标、顺序及意见，不提供像素路径。不得另行读取抠图图片或蒙版，不得将其传给 image_gen 或带入最近对话图像作为隐式参考；必须显式使用 generationInputs.allowedImagePaths 中的干净原图、当前输入及已完成的真实图层。不得按颜色阈值重新抠原图文字或拼回原图像素替代生成。遮挡和背景补全沿周边纹理、光照、透视合理延续，不添加无依据的新物体、不声称恢复不可见的真实内容。改尺寸统一换算图层坐标，不擅自裁切或拉伸。无原图的新素材遵循用户描述和指定参考；来源链不完整或原图不可读须明确说明，不虚构参考。

最终检查各层合成后的对齐、遮挡和边缘，与当前节点及最初原图未改内容比较；存在未授权差异时修复或如实报告，提示词本身不代表一致性已验证。普通矢量化继续使用已选引擎，不因本原则改为生图。

## 独立精细抠图 cutout

顶部“抠图”是独立本地功能，BiRefNet HR-matting / Lucida v7由服务自动运行，不需要领取或发送到Codex，不调用image_gen、不自动规划图层或矢量化。参数settings.matting与PSD预览设置独立。输出保留输入RGB（除非明确打开边缘去染色）及全画幅软alpha，新节点status=cutout。已透明输入也运行精细模型。不要将该正式抠图节点误标为预分层；不要把预分层重建“不保留预览像素”的规则应用于此独立功能。输入仅当前节点，预览取干净输入，已完成节点取可见合成；不处理上下游。

## 预分层 plan

图层规划列出名称、对象归属、原图坐标框和从底到顶顺序。背景层必须传 `role:background`，避免模型按前景抠掉背景。目标是快捷可理解的预览，不要求用户精修边缘。

规划时逐一检查遮挡关系：位于人物后方的城市背景和挡住人物下沿的前景桌面不能混为最底层；同类内容若跨越某物体的前后，按空间拆层。检查桌面斜边、产品接触阴影、倒影、细弧线和装饰光，明确每项归属。不能用生成框的直线边缘代替真实遮挡边缘。

- 方案2：识别图片语义和合理图层，调用 `canvas_apply_plan` 提交各层 box `[x,y,width,height]`。后端使用本地模型输出透明抠图缩略图，不将矩形裁切当作抠图。框只是模型提示区域。
- 方案4（BiRefNet HR-matting）/5（Lucida v7）：提交 box 和 role，后端直接从干净原图运行所选精细模型，使用请求冻结参数，不先粗抠；建议框需容纳发丝、光晕。不要静默切换模型或修改参数。
- 方案3（Codex 框规划）：只查看干净原图和当前干净输入，理解对象并提交名称、box `[x,y,width,height]`（整数像素）、role、opinion 与底到顶顺序。框明确该层重建画幅，名称/意见明确框内哪些对象属于该层；背景默认整图，其他层容纳发丝/阴影/光晕。严禁调用 `image_gen`、本地抠图或生成任何预览文件，不提交 path/url/svg。服务创建 kind=plan 的无像素规划层，显示原图及虚线框。提交后停止，等待用户确认；规划完成不等于真实重建完成。
- 使用者可在任何预分层模式中新建无像素规划层、命名、调整框、添加意见并排序/删除。任务以用户确认时的层列表与 frame 为准，不能因某层没有图片文件而忽略它，也不能擅自再次生图做预览。kind=plan 只是规划记录；正式回传必须转为真实 raster/text/vector 图层，不能回传空层。
- 预览只表示建议，不宣称恢复完整遮挡内容或最终分层。预览文件本身的位置与尺寸不因拖框而改变；独立 frame 是最终重建画幅，背景默认整图，其余默认预览范围（含上下文留白）。提交预览后等待用户拖动虚线框、调整并确认真实分层；不得自动跳过确认。

## 真实分层 layer / revise

针对简单实体方块/方环的真实模型形状失真，新v4首次prepare前可显式冻结RECONSTRUCTION.md的nativeGeometry四角/孔/实色配方并调用render-native-geometry。普通透明位图记录native-geometry-renderer真实身份，PS则在自己的native-shape路线实际制作和检查；不默认替换其他对象或复杂角色，不从源像素抠出轮廓，不把任何参数或局部通过当整体验收。

新任务使用重建流程 v4。先读 [RECONSTRUCTION.md](RECONSTRUCTION.md)，普通路线先layout明确元素唯一归属、排除项、参考定位点和接触/遮挡关系；独立层prepare → 当前对话image_gen → 原件register保存检查点；按关联组查看、纠正、review和composite检查叠放，最后review-composite和complete。精细/粗略抠图仅供预览。

- 固定150万像素预算（含透明留白）；保持每层冻结frame。返回尺寸由文件实测，原件/工作图/最终框分开。默认生图不能用SVG、字体或原图裁片代替生成，也不预缩放后冒称原件。只有新普通v4首次prepare前显式冻结nativeText的单层，可按RECONSTRUCTION.md改用真实字体渲染：v1水平，v2须事前冻结源平面的倾斜/斜切及局部墨迹框；必须如实登记native-font-renderer，不能冒称image_gen。v2只制作真实印字，不代替金属框、连续膜或水滴。
- 查看干净局部裁片与原图，准备元素清单；原图约束未改内容，当前已确认修改及用户意见优先。合并传sourceLayerIds全部ID，等比总图改尺寸传width/height。
- 新工具或字段未出现在当前MCP列表时，用项目bridge/cli.ts转发完整JSON，不降级规则、不新建对话、不让用户手动接单。
- 每层先实际生成、检查，再有针对性纠正，最多三次不同方法。允许根据真实对应定位点作统一缩放和平移，不能按alpha包围盒居中或改变形状。明显问题仍存在则needs-revision，自动红标继续，不以视觉漂移中止整单。无效/缺失文件不能伪装完成。
- stageOnly仅暂存；完成时每层传generationId、登记originalPath、来源ID和frame。验收以登记结果为准。保留源节点，创建新来源节点，不重做上下游。
- 普通生图路线输出位图层。需要原生文字、路径、变形和样式使用PS流程，不能临时换手写SVG；普通PSD导出遇到SVG会栅格化，须如实说明。
- 老任务未标v3仍可继续旧协议，但新执行应优先使用同样的登记。不要为了兼容而清空用户历史、预览或已完成文件。

## 矢量化

矢量化设置提供 Vectorizer.com 自动网页、Vectorizer.AI 官方 API、Recraft 官方 API、302.AI 转接 Vectorizer.AI。SuperSVG / AdaVec 已移除。免费网页由本地后台通过 Edge / Chrome 的公开上传/下载页面自动执行并回传，不要求手动导回，不调用隐藏接口、不绕过人工验证。网站条款限制第三方集成，浏览器方式仍有这一限制。官方 API 也由后台执行，使用独立 API ID/Secret 与月度 API 套餐，网页订阅不包含 API。302 使用独立的 302 API Key，不接受 Vectorizer.AI 官方密钥。不得擅自替换选择的引擎。API单独收费，不属于Codex额度。预分层透明缩略图不能当作完整图层矢量化。处理最终图层时各层独立转换再组合，保持顺序和坐标。最终纯矢量导出不含嵌入位图。

### Vectorizer.com：Codex 操作网页

设置 vectorizerComMode=codex 时，矢量化按钮排入当前对话 waiting_codex 队列。领取包 webVector 给出官网、逐层 uploadPath、layerId 和输出目录；Codex 使用当前可见浏览器逐层上传并观察转换，不改用后台上传脚本、API 或生图重画。全部转换完成后点击 REVIEW AND DOWNLOAD 进入公开结果页，读取该页面完整 URL，调用 canvas_web_vector(action:download,reviewUrl,baseVersion)。下载接收器通过已安装 Edge/Chrome 的公开结果页下载已有文件，不重新上传或转换；逐层校验名称、数量和纯矢量内容后自动创建画布节点。避免依赖内置浏览器未提供路径的下载事件，也不猜桌面/下载目录。失败保留已校验文件，原 jobId 可以续传；不得声称已完成。

遇到验证码或人机验证，调用 canvas_web_vector(action:status,phase:verification,message:需要用户在打开的网页完成验证)；保留浏览器页面和 running 任务，不绕过验证，不调用 fail，不因没有产物标记完成。告知用户完成验证后继续。验证完成后，使用原 jobId 调用 canvas_get_request 恢复，不重新领取；读取同一页面继续下载。

下载受阻用 status phase=blocked，明确原因。只有新节点已经创建才是完成；回读 completed 状态及 result.imageId，并在画布选中结果节点检查真实显示。下载接收器完成时会自动回传；若已通过浏览器获得实际本地文件，检查每个实际 SVG 后，调用 canvas_web_vector(action:complete,baseVersion,files:[{layerId,path}])。每个待转换输入必须恰有一个 SVG；已有矢量/文字层由后端保留，坐标、顺序和透明效果按冻结输入组合。不得用 canvas_complete_request 绕过对应关系检查。完成不会覆盖原图。此选项会消耗 Codex 额度；点击按钮后由桌面发送接口自动触发当前对话。

## Photoshop / Illustrator 最终兜底

**Photoshop 请求必须先读 [PHOTOSHOP.md](PHOTOSHOP.md)**，使用 `canvas_ps_rebuild` 的计划→素材→实际PS渲染→逐层/整图检查协议，不能直接提交一个PSD跳过验收。PS路线允许在设置启用时从干净原图准确提取；这是本节对上文普通生成流程禁止提取的明确例外，预抠图像素仍禁止使用。位图优先生成+PS合成，文字/形状优先PS原生。已完成原生PS节点的“提交PS修改”进入相同协议。

新PS任务使用v4流程：plan明确elements唯一归属、anchors/relations，canvas_generation登记原件，place-material按placementFrame装入完整素材智能对象。先原素材合成检查，再按设置upscale-material并重新置入复审。文字对照原图检查字形/倾斜/变形/样式，自己的PS参数与计划一致不证明视觉匹配。inspect-progress供中途叠放查看，最终inspect/review/review-composite绑定真实文件。局部裁片只作参考；定位后重新material/置入/检查，旧任务按实际版本兼容。

当前MCP缓存若没有v3工具、字段或操作，使用下文CLI发送完整JSON，不通过旧schema剥离新字段，不降低后台校验、不要求用户手动接单或重启。

用户点击交接按钮即请求将当前冻结素材和意见交给本对话执行。入口仅两个按钮，额度提醒由界面 hover 提供；不要增设用户必须读的“查看交接提示词”步骤。领取完整包，使用包内的明确应用交接提示词及 generationInputs 允许的干净素材。执行必须遵守：

- 先调用 `canvas_adobe(action:inspect)` 检查实际连接与工具清单；PS 支持项目隔离的社区 MCP，Illustrator 官方 MCP 需 Beta 本机 URL/密钥，正式版可通过 COM/ExtendScript。`action:call` 必须使用列出的真实工具及参数；`action:native_script` 执行本次 outputDirectory 内 JSX 并声明尚不存在的新输出。执行工具需已领取交接任务，且只允许原任务对应 PS 或 AI。
- 连接结果向用户分别说明 MCP / 脚本成功或失败，有一项失败即写清是哪项；不在主界面展示 JSON 或代码，技术信息仅在查看详情中提供。
- 核实本机应用与当前工具实际可操作，不能根据网上案例承诺当前能力。按本机可用工具执行，不能把复制提示词当完成。
- 原图和用户明确修改意见决定结果。保留所有 `keep` 图层及无须变动部分，对 `rebuild` 图层实施指定修复。不要自由重设计。全图2K意见应一致变换所有图层及位置。
- Photoshop保存真实分层PSD，尽可能重建真实可编辑文本、字体变换和原生效果。Illustrator保存真实原生AI，并另存SVG供画布；不改扩展名假冒AI，不把位图嵌进去冒充纯矢量。
- 原生 AI 必须同时回传 SVG 或矢量图层，不能只返回 AI 文件就宣称画布可预览。保存新文件、重新打开检查、与原图对齐检查后提交实际文件。无法满足的原生效果/文字必须明确保留方式和局限。当前工具不可操作应用时记录失败，已有素材和意见保留，不报成功。

## 工具未刷新时

安装插件后如果当前任务尚未加载 MCP，可通过本插件项目根目录的 `bridge/cli.ts` 调用相同接口，不另起推理会话。调用形式为 `node --import tsx bridge/cli.ts <toolName> <arguments.json>`；参数文件保存在当前任务项目中。工具文件读取和 API 都经同一任务归属和版本校验。

升级后若当前会话缓存的 canvas_complete_request 参数列表尚无 review，使用上述 CLI 回传完整 review，不能省略视觉检查或将旧“漂移即停止整批”规则继续用于新任务。任务包中的 reviewPolicy 是当前执行契约。

默认重建的源像素禁用规则保留。新任务若明确采用RECONSTRUCTION.md的满幅背景保护窄例外，必须首次prepare前冻结独立背景选区与真实补全来源；只保留确认可见背景，预抠仍仅规划，不能复制文字/前景或原图垫底，也不能将派生冒称image_gen或视觉已通过。
