# 分层画布

这是 Windows 本地 Codex 插件。全程使用打开画布的当前真实任务 ID。所有模型推理、生图和修改留在当前对话，不能新建/分叉 Codex 任务或另起 `codex exec` 推理进程完成请求。不要通过独立 API 调用 OpenAI 来代替当前对话额度。

## 打开、导入与当前任务

1. 从当前执行上下文或环境 `CODEX_THREAD_ID` 确认真实任务 ID。没有证据时不要猜 ID。调用 `canvas_open(taskId)`，再用 Codex `open_in_codex` 把返回的完整 URL 放到当前任务右侧。
2. 用户要求把当前图片放进画布时，使用实际生成工具返回的原文件绝对路径调用 `canvas_import`。可上传 PNG/JPEG/WebP/PSD/SVG。缺少原图时不能用聊天截图代替。多张图片分别导入，保留各自身份。
3. 工具里的 `taskId` 必须是当前任务；不得复制旧任务 URL。图层与标注坐标使用输入图片像素，与浏览器缩放和画布坐标不同。箭尾和文字允许在图外，箭头末端是目标。领取包 coordinateAnnotations 给出图片/图层 ID、点、框、笔刷轨迹和独立黑白选区 maskPath；sourcePath 是干净输入，originalSourcePath 是沿来源链找到的最初原图（只读辅助参考，可能来自已删除节点的素材存档）。当前节点、已确认修改和本次意见优先，不得因原图差异撤回已确认修改。originalReference.complete=false 表示来源链不完整，不得声称已找到最初原图。只读取参考，不执行任何上游任务。不要将画布带标注截图传给生图代替原图；实际工具不支持蒙版参数时只能作为位置提示，不能声称硬约束。

## 接收画布请求

画布按钮保存冻结请求后，通过已安装的官方 Codex App Tools MCP 的 `send_message_to_thread` 自动发送到该画布绑定的当前对话。无需用户开启接单、手动发“处理画布请求”或让对话常驻轮询。此发送保持原对话及其模型设置，不使用独立推理会话。

收到自动消息时，只读取并处理消息里的精确 jobId。先核实 taskId 与当前真实对话一致；请求已取消、完成或失败则停止，已被领取的请求不要重复领取。`canvas_wait_requests` 仅用于用户明确要求批量处理或等待，普通打开画布不应无限占用对话。发送回执只表示送达，不表示实际执行或生成完成。发送失败由画布显示可理解的原因，不要让用户手动接单掩盖故障。

桌面连接由 `canvas_open` 自动刷新，只使用官方 MCP 服务及宿主传入的连接环境。不写 Codex 私有数据库，不调用私有桌面协议，不用独立 CLI 队列冒充桌面对话唤醒。历史未发送任务不会在升级或重启后自动执行。

每次仅处理请求 imageId 对应节点。父子连线只表示来源，不是执行链；不得自动处理上下游节点的分层、矢量化或修改，也不得自动从预分层继续生成或矢量化。正式完成产物创建关联新节点。

领取包包含冻结的 `taskId / documentId / imageId / version`、原图、图层、本地素材、总图意见、逐层意见、标注和请求类型。先看实际原图及有关图层，不能只读文字猜图。保留这些 IDs 和输入版本直至回传；切换当前选中图片不能改变请求归属。

## 预分层 plan

图层规划列出名称、对象归属、原图坐标框和从底到顶顺序。背景层必须传 `role:background`，避免模型按前景抠掉背景。目标是快捷可理解的预览，不要求用户精修边缘。

- 方案2：识别图片语义和合理图层，调用 `canvas_apply_plan` 提交各层 box `[x,y,width,height]`。后端使用本地模型输出透明抠图缩略图，不将矩形裁切当作抠图。框只是模型提示区域。
- 方案3：使用当前对话内置 `image_gen`，给出原图实际参考，按原位置生成粗抠透明预览，实际拿到并检查文件后通过层的 `path` 提交。不要把方案3静默改成本地模型。
- 预览只表示建议，不宣称恢复完整遮挡内容或最终分层。提交预览后等待用户在画布调整并确认真实分层；不得自动跳过确认。

## 真实分层 layer 和修改 revise

1. 读取全图意见、所有层意见和标注；UI只显示选中层的意见不意味着其他意见不存在。箭头可表达“这个对象归另一个图层”。图层顺序从底到顶。
2. 仅支持方案2和3：使用原图、预览及坐标标注给 `image_gen` 重建实际最终图层，补全背景与遮挡。方案1已移除，历史任务不得静默执行。
3. 每次生图必须用实际原图/对应输入层作为引用，并明确要求相同构图、相同物体、相同坐标和画布尺寸。局部修改只改变目标内容。透明背景必须是真实 alpha，不能把棋盘图案当透明。
4. 生成完成后查看实际产物。检查尺寸、对齐、透明度、边缘、背景补全和整体一致性。不要将无关生成图、空图、低分辨率预览或只改名的文件回传。
5. 文字：只有已建立真实文本内容、已知可用字体、位置字号色彩等参数时才声明可编辑文字。可通过 `psdStyle.stroke` 提供描边颜色和大小，通过 `psdStyle.shadow` 提供投影颜色、模糊、偏移和不透明度；修改现有文字传 `textDirty:true`。是否可编辑取决于 PSD 写入和实际回读结果；不能宣称支持全部原生效果。任意艺术字不能自动恢复原字体，不可还原的保留独立像素层；纯矢量时使用路径。
6. 原图和已确认图层不覆盖。提交 `canvas_complete_request` 使用领取时 `baseVersion` 与实际图层文件路径。保留每层位置、名称和顺序。全图尺寸变化时同时传输出 `width` 与 `height`，各层尺寸和坐标按最终画布统一换算；交接PSD/SVG通过 `artifactPath` 返回时服务读取文件实际尺寸。正式产物在画布创建关联新节点；提交后用户有新意见时结果标记基于旧版，不覆盖新意见。不要强改 baseVersion；它必须对应领取时的冻结版本。
7. 执行失败使用 `canvas_fail_request` 记录可理解的原因。不编造产物，不把“请求已排队”当完成。

## 矢量化

矢量化设置提供 Vectorizer.com 自动网页、Vectorizer.AI 官方 API、Recraft 官方 API、302.AI 转接 Vectorizer.AI。SuperSVG / AdaVec 已移除。免费网页由本地后台通过 Edge / Chrome 的公开上传/下载页面自动执行并回传，不要求手动导回，不调用隐藏接口、不绕过人工验证。网站条款限制第三方集成，浏览器方式仍有这一限制。官方 API 也由后台执行，使用独立 API ID/Secret 与月度 API 套餐，网页订阅不包含 API。302 使用独立的 302 API Key，不接受 Vectorizer.AI 官方密钥。不得擅自替换选择的引擎。API单独收费，不属于Codex额度。预分层透明缩略图不能当作完整图层矢量化。处理最终图层时各层独立转换再组合，保持顺序和坐标。最终纯矢量导出不含嵌入位图。

### Vectorizer.com：Codex 操作网页

设置 vectorizerComMode=codex 时，矢量化按钮排入当前对话 waiting_codex 队列。领取包 webVector 给出官网、逐层 uploadPath、layerId 和输出目录；Codex 使用当前可见浏览器逐层上传并观察转换，不改用后台上传脚本、API 或生图重画。全部转换完成后点击 REVIEW AND DOWNLOAD 进入公开结果页，读取该页面完整 URL，调用 canvas_web_vector(action:download,reviewUrl,baseVersion)。下载接收器通过已安装 Edge/Chrome 的公开结果页下载已有文件，不重新上传或转换；逐层校验名称、数量和纯矢量内容后自动创建画布节点。避免依赖内置浏览器未提供路径的下载事件，也不猜桌面/下载目录。失败保留已校验文件，原 jobId 可以续传；不得声称已完成。

遇到验证码或人机验证，调用 canvas_web_vector(action:status,phase:verification,message:需要用户在打开的网页完成验证)；保留浏览器页面和 running 任务，不绕过验证，不调用 fail，不因没有产物标记完成。告知用户完成验证后继续。验证完成后，使用原 jobId 调用 canvas_get_request 恢复，不重新领取；读取同一页面继续下载。

下载受阻用 status phase=blocked，明确原因。只有新节点已经创建才是完成；回读 completed 状态及 result.imageId，并在画布选中结果节点检查真实显示。下载接收器完成时会自动回传；若已通过浏览器获得实际本地文件，检查每个实际 SVG 后，调用 canvas_web_vector(action:complete,baseVersion,files:[{layerId,path}])。每个待转换输入必须恰有一个 SVG；已有矢量/文字层由后端保留，坐标、顺序和透明效果按冻结输入组合。不得用 canvas_complete_request 绕过对应关系检查。完成不会覆盖原图。此选项会消耗 Codex 额度；点击按钮后由桌面发送接口自动触发当前对话。

## Photoshop / Illustrator 最终兜底

用户点击交接按钮即请求将当前冻结素材和意见交给本对话执行。入口仅两个按钮，额度提醒由界面 hover 提供；不要增设用户必须读的“查看交接提示词”步骤。领取完整包，使用包内的明确应用交接提示词。执行必须遵守：

- 先调用 `canvas_adobe(action:inspect)` 检查实际连接与工具清单；PS 支持项目隔离的社区 MCP，Illustrator 官方 MCP 需 Beta 本机 URL/密钥，正式版可通过 COM/ExtendScript。`action:call` 必须使用列出的真实工具及参数；`action:native_script` 执行本次 outputDirectory 内 JSX 并声明尚不存在的新输出。执行工具需已领取交接任务，且只允许原任务对应 PS 或 AI。
- 连接结果向用户分别说明 MCP / 脚本成功或失败，有一项失败即写清是哪项；不在主界面展示 JSON 或代码，技术信息仅在查看详情中提供。
- 核实本机应用与当前工具实际可操作，不能根据网上案例承诺当前能力。按本机可用工具执行，不能把复制提示词当完成。
- 原图和用户明确修改意见决定结果。保留所有 `keep` 图层及无须变动部分，对 `rebuild` 图层实施指定修复。不要自由重设计。全图2K意见应一致变换所有图层及位置。
- Photoshop保存真实分层PSD，尽可能重建真实可编辑文本、字体变换和原生效果。Illustrator保存真实原生AI，并另存SVG供画布；不改扩展名假冒AI，不把位图嵌进去冒充纯矢量。
- 原生 AI 必须同时回传 SVG 或矢量图层，不能只返回 AI 文件就宣称画布可预览。保存新文件、重新打开检查、与原图对齐检查后提交实际文件。无法满足的原生效果/文字必须明确保留方式和局限。当前工具不可操作应用时记录失败，已有素材和意见保留，不报成功。

## 工具未刷新时

安装插件后如果当前任务尚未加载 MCP，可通过本插件项目根目录的 `bridge/cli.ts` 调用相同接口，不另起推理会话。调用形式为 `node --import tsx bridge/cli.ts <toolName> <arguments.json>`；参数文件保存在当前任务项目中。工具文件读取和 API 都经同一任务归属和版本校验。
