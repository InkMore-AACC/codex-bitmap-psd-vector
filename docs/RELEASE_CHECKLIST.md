# 发布检查单

1. 等待画布任务结束并保留用户数据。整理版本说明、功能边界、安装和教程，核对过时入口。
2. 使用 `python scripts/prepare-release.py <新的空目录路径>` 导出白名单快照。不要直接上传原始 Git 历史或整个工作目录。
3. 检查排除：data、模型、运行时、node_modules、dist、.mcp.json、本机路径、私人任务ID、截图、开发证据、参考论文和账号凭据。工具模式扫描不能代替人工审查。
4. 在快照目录安装依赖，运行 `node scripts/configure-plugin.mjs`、`npm run typecheck`、`npm run build`、`npm test`。生成的本机配置保持忽略。
5. 核对 Markdown 相对链接，确认安装不依赖未发布素材，说明未验证的真实外部服务与新机器兼容性。
6. 查看最终 Git 提交文件清单及大文件；只推送清理后的历史。不要加入凭据到远程URL。
7. 推送后从 GitHub 回读仓库可见性、提交ID和文件树，确认一致后才告诉用户上传成功。

本次完整测试在开发环境运行54项通过（含长路径回归）；公开快照的独立依赖安装、构建及测试另在 ACCEPTANCE.md 记录。源码公开不自动选择开源许可证。
