# 常见问题

## 重启 Codex 后画布像是空白或新建的

插件连接加载时会自动启动画布服务；关闭标签不退出后台。所有关联 Codex 宿主退出后，完成本地任务和保存，再空闲约15–20秒停止。网页已加载时会对初始读取的网络失败重试最多30秒。如果浏览器自身先显示“无法访问此页面”，请刷新，必要时调用“打开分层画布”。这与 Codex 对话的 `stream disconnected` 网络重连是不同问题。

画布节点保存在本机 `data/documents/`，与右侧面板是否打开无关。当前版本会为本机访问凭证设置持久 Cookie，并为每个画布单独保存缩放、位置和最后选中的图片；重新打开同一 Codex 对话时会显示“已恢复 N 个节点”。如果凭证确实失效，页面会明确提示回到当前对话说“打开分层画布”，重新连接不会删除历史。

| 现象 | 先怎么做 |
|---|---|
| 找不到插件工具 | 确认安装注册完成并重新加载插件；新对话检查工具清单，不要把构建成功当成安装成功 |
| 画布打不开/拒绝访问 | 从目标 Codex 对话重新说“打开分层画布”，使用返回的新链接；不要自己拼 taskId 或复制别人的访问令牌 |
| 请求发送失败 | 展开原因。确认官方 Codex App Tools、桌面宿主连接和当前真实对话绑定可用；重新打开画布刷新连接。不要伪造接单状态 |
| 已发送但未完成 | 当前对话可能忙。发送不代表生成完成；看对话是否实际领取了该 jobId，不要反复提交 |
| 执行中但没有新节点 | 让 Codex检查该任务的输出文件、回传及完成状态；下载成功但未回传也不算完成 |
| Vectorizer.com 弹验证 | 由用户完成验证后继续；不要绕过验证码。自动脚本失败可取消后选择 Codex 操作网页，旧失败任务不会自动变成新模式 |
| API 401/403/余额不足 | 检查选中服务商、该服务商的独立凭据和 API 余额；网页订阅不一定含 API |
| 模型未安装 | 方案2运行本地模型安装脚本；方案4/5加 -FineMatting；也可选方案3。模型下载失败看来源和摘要校验，不关闭校验 |
| Adobe 部分成功 | MCP 与 Windows 脚本是不同通道。展开详情区分哪一项失败，实际复杂编辑仍需验证 |
| 显示原图不可用 | 先选一张图；等原图信息读取完成。缺少来源链时不能保证找到最初原图 |
| 标注突然不见 | 取消选择、多选、框选和原图对比会隐藏标注。回到结果并只选一张图片查看 |
| 保存冲突 | 停止继续编辑并保留输入内容，让 Codex检查并发版本；不要直接用旧文档覆盖服务器 |

## 预分层完成后提交提示“输入格式不正确”

提交前会自动保存整张画布，历史结果中的元数据也会参与校验。旧分层结果的 `generationAdaptation.offsetX/offsetY` 可以是负数，表示素材在设计框左侧或上方延伸；不能把它们当作只能为正的补边宽度。当前保存校验接受有限的正负偏移，保留实际位置，不截成零。修复后重载本地服务即可继续保存和提交，既有原图与预分层无需重做。若页面还有未保存修改，先下载草稿；其他输入格式错误仍需检查具体数据，不能直接视为此问题。

## 部分 MCP 工具被跳过

如果 Codex 日志提示 `Skipping MCP tool`、`failed to build tool spec: invalid type: map, expected a string`，检查实际 `tools/list` 返回的数组定义。旧桥接会把坐标、颜色等固定长度元组输出为 `items: [{...}, {...}]`；这会影响生成、PS重建、规划、抠图旧入口和完成回传五个工具。

当前桥接只在对外工具定义中将这些元组转换为单一 `items` schema，保留长度约束；各位置不同的限制同时写入说明。实际调用仍经过原始 Zod 与后端校验，不放宽坐标、颜色或审核规则。修改源码后须等宿主重新加载插件，才能检查宿主是否重新接受这些工具；独立 MCP 测试通过不等于当前对话已重载。若另有 `/codex/responses` 返回 HTTP 400 `Bad Request`，应单独检查，不能仅凭这些工具警告就认定两者存在因果关系。

## 给 Codex 的排查顺序

### 多轮看图后 Codex 报 `{"detail":"Bad Request"}`

先区分画布 HTTP 错误和 `chatgpt.com/backend-api/codex/responses` 的拒绝。公开案例显示图片内联历史可能很大，而 token 计数仍未达到上限：[图片字节与 token 不一致](https://github.com/openai/codex/issues/41338)、[Windows 工具成功后仍报错](https://github.com/openai/codex/issues/43711)。这些是未关闭的用户报告，不能只凭同样错误就确认根因。

读取对应对话日志的请求字节数，并检查图片是否能解码、是否为空、是否存在失败的压缩和缺失的工具结果。之后的视觉检查使用 `node scripts/review-image.mjs <source> <new-preview.jpg>` 生成有体积上限的查看副本；原件保留，细节用原坐标局部，透明度与精确差异仍测量原件。仅新开对话但继续大量直接回传原图，可能很快复发。不要盲目删除登录信息、改全局模型或安装代理。**不要直接缩短或重写已索引的 Codex 会话文件，即使像素与消息完全保留、已归档卸载也不安全**：分页历史按字节偏移读取，可能因此永久停留在旧错误。后台完成、磁盘有结果、官方对话读取能看到最新回合是三个需要分别确认的状态。若日志有 `durable rollout shrank before projection`，应先处理历史索引与文件不一致，不能据旧报错反复重做已完成任务；插件不得直接改写私有索引数据库。

1. 读取具体失败消息与当前 taskId / jobId，不领取其他历史请求。
2. 区分服务存活、鉴权、对话发送、生成执行、下载、回传、前端显示。
3. 使用只读检查先找问题；当前请求取消/完成后不能重复执行。
4. 如需重启服务，先确认无运行任务且画布已保存，核对进程身份。保留所有 `data/` 和原始素材。
5. 解释已经验证到哪一步，不能用“节点已创建”代替“文件内容正确”。

## 报告问题

请提供 Windows / Codex 版本、选择的方案或服务商、操作步骤、预期和实际结果。可以附打码的截图与简短报错。不要公开 `data/service.json`、密钥、带 token 的链接、私人图片或完整对话。为复现准备一张自己有权公开的非敏感图片更有效。
