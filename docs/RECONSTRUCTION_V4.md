# 重建流程 v4

新context-only与concise-edit组合的prepare精简重复流程说明，保留全部动态用户意见、标注映射、冻结定位/alpha/遮挡关系、排除项和执行说明。源文字观察若含整图坐标，不得直接当作参考文件坐标；本文件定位采用后台已有冻结映射的百分比，不改变源点或frame。旧prepared提示与默认双参考流程不重写。这是针对r25银字仍扩大/变形的提示歧义修复，改善视觉一致性尚需新的真实候选验证；青光局部通过不能代表字形或整图验收。

新prepare可额外显式设置referenceContext.referenceMode="context-only"，并使用referenceStrategy="local-only"：仅完整周边首图进入模型，不再附旧框局部或全图；不能同时启用detailReferences。未设置此模式时保持旧有序引用及提示。旧局部继续作为只读来源保存localPath/localReferenceHash，用于定位和matte校验，不能作为生成素材；登记、后续使用及异步结束都核对冻结摘要，原样及相同RGBA重编码别名拒收。该模式用于验证双参考构图冲突假设，尚未证明改善真实一致性，不能迁移旧请求或移动源定位点。

实际候选出现固定细结构被重画、且仅坐标文字纠错无效时，下一次准备可用`detailReferences`提供原图中对应位置的干净细节。最多3处、合计262144实际输入像素，不放大。第一张完整构图仍决定输出，额外裁片只帮助模型辨认位置与外观；不能贴回裁片、传预抠蒙版、把细节当新构图或声称硬约束。必须在prepare时冻结，使用返回的完整有序参考登记；之后用真实输出检验是否改善。

这次修复针对真实失败记录中的问题：RGB背景登记报错、狭长图层被留白挤小、定位限制迫使缩窄、弱透明像素越框报错、只写模板检查、重复光效和层间接触失配。

## 对设计师的变化

画布的分层框、标注、节点与修改意见交互保持原样。新任务的后台先明确元素归属和层间关系，然后逐层制作与合成检查。真实检查已确认失败的层可立即红标，其他层继续，成功层保留。

150万像素的生成/工作图预算不变，透明区域计入。虚线框是最终设计范围，不等于工具返回文件的像素边界。特别狭长的透明图层增加透明外沿，以约3:1承载；新v4滤色光效增加纯黑中性外沿，以约2.5:1承载，参考同步留边并保留局部细节，最终仍按完整carrier定位。这是依据实际狭长光效画幅偏差采取的包装策略，不是模型官方能力或精确尺寸保证；增加留白可能降低物体实际可用像素。旧prepared请求/原件/检查窗口不迁移、不重裁或拉伸。生成后仍须核验原位裁断、曲率、亮芯数量和衰减，不能以承载比例符合替代光效及整图验收。

生成原件、预算内工作图、实际放置位置分别保存。定位由生成前冻结的原参考特征点决定，不再限制为默认缩放的±25%，也不能事后改参考点。只允许统一缩放和平移；内容形变仍需生成纠正。越框的弱透明像素保留在PSD层内，不剪掉后假装尺寸合格。

新精简生成提示在有真实局部参考时保留冻结特征在第一张完整参考文件中的横/纵百分比，包含扩展外沿；旧版本精简提示只保存这些点供登记后定位，没有把它们传入生图。没有局部参考、首图退回整图时不传局部百分比，保留无精确局部依据的说明。百分比用于指认原有特征，不绘制标记，也不保证模型遵守。选择可重新识别的具体交点或字形并记录人工误差；“某边附近”无法确定同名点时，不任意选候选边缘强行拟合。旧prepared原文/源点不追溯修改；修复仍待下一张新复杂海报验证，不能以提示传递检查通过声称实际偏移已解决。

调用真实生图前，先把prepare的第一张干净参考与同坐标整图局部对照。若规划框裁断原图中仍可见的笔画/轮廓，这是参考准备失败，不能当作原图固有裁断或继续付费生成。保留未调用的请求及失败观察，旧frame、定位点和prepared不追改。新prepare可显式使用`referenceContext:{marginPixels:1..128,observation}`：普通/PS normal透明前景及已声明独立screen光效从当前干净源重新取周边，第一张覆盖完整新carrier，第二张旧框局部仅供对照；实际本层框外可见轮廓原位保留，其他层排除，整图外normal透明、screen纯黑。旧默认包装不变，背景/源保护/aux及旧流程拒绝，screen仅限独立light/light-effect。内容摘要缓存避免同路径更新仍使用旧裁片，准备期间源/状态/PS完整计划改变则旧请求拒收。该机制仍须真实字形、原位及整图独审，不能以参考恢复完整代替重建成功。

插件改进循环以一张全新复杂海报为一个实验轮次，轮内各层候选或对齐不是新轮次。每轮新图包含密集文字、角色、独立光效和材质遮挡，并针对上一轮真实失败布置可观察的验证点。先执行能验证修复假设的真实双路输出和相关组合对照；已有充分失败证据时，可将本轮明确结束为失败，记录未制作层、未完成合成与未审核事项，保留原图、冻结任务、所有候选和文件，再修正插件或循环规则并换下一张针对性复杂图。失败轮不要求为凑齐层数继续无收益生图，也不能把一次层调用称为新轮。没有有依据的修复或新测试设计，不反复换图。

失败轮结束不代表目标完成。成功验收仍要求完整普通重建和真实原生PS文件、全部语义层与独立光效、遮挡补全、文字外观、实际整图合成对照、回传可见及独立整体验收；局部通过、测试通过或少量填充组不能替代。验证优先复用现有实验驱动与生产接口，不为每个图层复制一套临时执行程序。普通用户的完整重建请求仍按冻结任务继续和如实红标，不因本实验的失败退出规则被擅自终止。

干净裁片缓存是只读证据：新prepare复核现存文件与同次捕获源按frame导出的PNG字节。不一致则保留文件、拒绝使用，不把受改写缓存的新摘要包装为真实源证明。诊断参考存在不表示prepare或生成成功。

新计划冻结前必须回看定位点的实际落点。用`scripts/review-anchor-points.mjs <source.png> <proposal.json> <new-diagnostic.jpg> [proposalId]`检查含真实taskId/sourceHash/width/height/units的草案：每行左侧是未标记原尺寸源窗的2倍查看图，右侧是同窗的坐标十字，逐点确认名称和人工误差后才能冻结。单批1–8点、JPEG≤128KiB，当前任务先检查只读上下文预算；源文件不变。诊断不进入referencePaths或正式素材，也不自动确认语义。冻结后发现源点记偏，保留错误记录，不用错误目标align，不把对错误点的差值称为生成漂移；另外记录真实源特征和候选观察，在后续新计划修正。此项来自r18左耳机字标源点误记，既有冻结点及候选不追溯改写。

复杂海报插件改进循环中，作者单独勾选“已核对”不够。r19源T十字已看但仍落在金属灰面，说明诊断图片与自我确认不能替代独立源点读回。新的草案先声明`limits.manualAnchorErrorPixels`，在冻结及任何实际生成前取得独立同名特征读回，再执行`node scripts/review-anchor-points.mjs --check-review <source.png> <proposal.json> <independent-review.json>`。独审记录含真实taskId、sourceHash、proposalSha256、accepted状态、不同的authorId/reviewerId及完整observedAnchors（proposalId/name/proposedPoint/observedSourcePoint/measurementErrorPixels/sourceFeatureMatched）。每点距离加读回误差必须不超过事前声明误差，歧义、遗漏、重复、改点、needs-revision、自审或来源变动均拒绝；冻结时重新校验来源/草案/独审摘要。检查只读，不验证审核者身份、不自动识别字形或证明语义真实，不能用假身份或同一作者的转写冒充独审。未锚定组仍明示限制，不能编造点。旧冻结误标与失败继续保留，不追溯补独审通过。

## 执行流程

普通重建：元素归属/接触规划 → 单层生成 → 原件登记 → 实际对比/纠正 → 本层审核 → 实际合成查看 → 下一层 → 全部合成逐项审核 → 新结果节点。

材质规划先于重复生成，但不固定拆成实体盒、盖框、薄玻璃三组。新的复杂图按实际组件边界选择：自然连通的薄面与实框若拆后反复双归属，可试验完整盖组件与实体盒/耳机分组；薄面透底和实框覆盖分别检查，不能统一减淡整盖。确需分材质时，事前确认其内部边界和相互排除范围，后景RGB始终归后层。每组在生成前从原尺寸参考冻结至少三个分散可识别特征；只允许按冻结名字等比平移定位，随后对照未参与拟合的框角/铰链等特征以及全轮廓、字滴纹理。最终放置后核对检查窗是否覆盖实际素材，落在载体外的clear通过不能证明整条兄弟边界隔离。透明数值、三点残差或背景减少均不替代完整层与同坐标叠图审核。此规则依据r15普通拆分失败和PS自然盖局部实证修订，是未来新图的待验制作策略，不是自动分割算法或整体验收。当前冻结组、点、检查窗/阈值、原件和失败收据保持，不追溯重组或自动重做。仅当冻结计划含transmissive区域时，生成提示把“保留颜色与反射”限定为本层固有外观：单张源图的薄透像素已混合后景，明确归后层的RGB须与alpha一起重建，不能复制为近不透明纹理或只减整层opacity；不确定反射不自动当污染删除。此处仅消除提示冲突，不提供局部硬蒙版或RGB去背景算法，修复是否有效须在下一张新复杂源上验证。

循环以修复插件和制作策略为目标。一次候选真实失败并记录审核后，可以停止该层分支；继续本轮其他组须有明确验证收益，充分失败证据可按上述规则结束失败轮。不得把薄材质反复失败当作外部阻塞，也不得把每次层调用误算为新轮。三次制作是上限，RGB残留的当前候选不继续只减alpha的matte分支。所有区域先检查整图/来源框范围再提交；计划修正保留旧版本和失败回执，生成后不移动检查窗或降低阈值接受失败。数值、编码、代码测试通过都不替代实际图层/整图对照与回传可见验收。

若真实图层和部分合成已证明可解释的失败，且剩余组不会验证拟修机制，可保留缺失清单与失败证据，先修插件，再用下一张有针对性的新复杂图验证；不为填满失败样本而继续无依据生成。结束失败轮次不是结束整体目标，最终两路验收仍要求完整实际输出、全部元素和层间关系对照、独立审查及回传可见。

薄材质内部接近不透明时，可在新普通v4计划中显式冻结`allowAuxMatte:true`并提供`transmissive`区域检查，受控试验“真实RGB候选 + 独立生成灰阶matte”。仅单个normal透明前景支持，无默认启用，PS本次不支持。先登记并定位RGB，再prepare的`matteForGenerationId`准备辅助请求；引用仅为精确的完整基底工作carrier与该请求clean local。用当前对话image_gen输出完全不透明灰阶PNG并register辅助原件后，显式`derive-alpha`。辅助ID不能当图层候选；后台新派生记录双来源，固定`A=min(oldA,M)`，RGB逐通道不变，原件与150万预算/完整几何保留，禁止全层opacity、曲线或阈值后调。全白、全空和整体统一灰伪修拒绝。

这个方法处于实验阶段：服务校验不能证明matte语义正确，也不能修复RGB中的城市残留、错发束或纹理。通过区域检查后仍须查看真实深浅底和最终合成，失败可标红，不强制不断直接重试RGBA。文件、来源、规则和定位变更使双链审核失效；派生不能再定位后丢弃matte。RGB prepare实际请求也冻结可选allowAuxMatte，缺字段不迁移，事后开layout不能追溯授权；已知辅助/派生文件路径、字节摘要或完整尺寸与精确解码RGBA身份的别名不得重登记image_gen或从旧普通缓存回传。只改PNG元数据/压缩且像素完全相同也属于同一角色；私有缓存基于真实文件摘要，旧误登记记录无需新增字段即可重验。不识别相似图、有损改写或重采样。具体登记/派生字段与兼容边界见CONTRACT.md。

若真实辅助PNG只是轻微近中性RGB，下一次新aux prepare可明确选`matteEncoding:"near-neutral-luma8-v2"`；缺字段及exact-gray8-v1仍严格精确灰，不追溯放宽旧失败。v2先检查完整raw为8位PNG/全alpha255，全图通道spread≤16；maxRGB>8材质平均spread≤2，至少99.9%材质像素spread≤8。通过后按固定`round((2126R+7152G+722B)/10000)`转scalar，再完整carrier预算缩小。实际原件保留，working是内部标量场，编码/统计/公式/原hash和位置仍递归绑定，不能重新标成image_gen或调曲线来通过；这些阈值只认证输入编码，不代表材质视觉正确。

新aux请求可显式选择`near-neutral-luma8-v3`，仅移除全图单点spread≤16；完整raw PNG8/alpha255、材质mean≤2及99.9%spread≤8和固定luma顺序全部不变。maxSpread仍实测登记；缓存、证明与双链按编码版本隔离，v1/v2旧请求和失败不改写。零星彩色点可能是轮廓几何风险，编码允许不等于视觉允许。

新普通v4 normal透明前景可在首次生成前显式冻结`opaque`区域：仅name/box/minAlpha(1–255)/minPassingFraction，不带max/response，无默认。按实际最终放置RGBA中alpha≥minAlpha的像素比例检查，并纳入辅助prepare的下限必要条件；PS/screen/背景/旧workflow拒绝，旧无opaque请求不补字段。实体固有黑色或印字仍需保留覆盖形状，不能按RGB明暗决定透明；实际失败阻止accepted及伪通过缓存，仍可诚实红层回传。它不修RGB、形变或自动接受全图。

准备辅助matte前还会按真实working和实际整数放置新测minAlpha必要条件。每个冻结薄材质区域中alpha已达到minAlpha的像素须至少ceil(区域像素×原通过比例)；不足时减alpha算法无法补回已清空材质，直接拒绝准备，不产生辅助请求/引用/文件或修改登记。少量透明像素按原容差处理，alpha255仍算可降低的有效像素。通过此必要条件不代表灰matte成功，更不批准RGB背景污染、材质缺失、定位形变或视觉；普通失败RGB仍可needs-revision。旧辅助链不追溯更改，阈值与原件不降低或改写。

后台生成对比图已统一到实际放置坐标，不再分别把原件与参考塞进不同的缩略图比例。通过记录须有位置、外观、分离三项具体观察。红标记录至少一次真实已检查制作与未解决问题，不强制第二候选或成功定位；报错API不算有效制作。最终候选、文件与合成审核绑定，变化后重新检查。

显式周边请求的单层对比视窗覆盖完整carrier，用第一张周边参考对照实际放置结果；登记、定位及alpha派生均保留设计框外的待审核笔画。`comparisonFrame`仅记录审核范围，不改变冻结设计框或素材。旧请求、历史审核与对比原件不追改，完整字形与纹理仍须实际审查。

周边prepare首次冻结定位点时，允许使用设计框外、完整周边参考内的真实可辨认特征；范围为carrier与整图canvas交集，不含画外透明留白。align从已冻结请求取得范围，局部target允许负值或超出设计框，但仍须对应原anchorNames及源坐标，不能看完候选后移动目标。没有周边字段的旧流程继续使用设计框限制。此修复解决r25银字尖角已在真实周边内、却被旧框定位检查拒绝的问题；接口通过仍不证明字形重建成功。

PS：计划/原生与生成路线 → 工作素材合成 → 中途PS预览 → 实际PS检查和逐层审核 → 像素不足且设置开启时超分 → 重新置入/审核 → 整图关系检查 → 原生PSD新节点。inspect-progress导出当前ready素材的全部对应组及深浅底，不再只导出声明alpha区域的组；仍仅对事前声明区域进行数值诊断，无区域不表示alpha通过，processing/缺失素材不作为已就绪组。中途预览不改变计划、素材、审核或最终验收状态。黑底滤色与透明素材的生成参数分别处理。文字检查同时比较原参考字形外观与PS事实；字体和变形参数相同不等于视觉一致。
