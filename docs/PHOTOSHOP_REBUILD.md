# PS 逐层重建

新v4 PS计划可事前显式冻结`nativeGeometry`，将简单实体定位符从随机位图生成改为真实PS可编辑实色形状。仅适用于独立v2 opaque-structure、native/shape/native-shape透明层：1–8个实色凸四边形，每个可有一个严格内含的四边形透明孔。四角、RGB及源观察在首次prepare/素材/原生制作前冻结；拒绝文字、复杂轮廓、纹理、薄膜、光效、背景、fallback和事后拟合。它不读取源像素、裁片或mask来产生输出。

调用`render-native-geometry(layerId,inputPsdPath)`，仅在本job PSD新副本的空目标组制作，保持已有打开文档。真实PS保存后回读形状名称、顺序、四角/控制点、实色、孔的subtract操作和可见性，partial/final inspect均重复此检查。含留白总画布仍限150万像素；不临时缩放路径，不放宽配准置信门槛。制作/metadata通过不等于源视觉通过，仍需真实透明及深浅底导出、区域alpha、与源四角/高度/倾斜和整图对照。收据可复用但不重复制作，恢复同job原生准备文件不创建结果或验收。

入口仍是“交接 PS”。任务在当前 Codex 对话执行，完成后创建关联新节点，保留原节点。默认以一致性优先，其次才是编辑能力。

当前新任务使用重建 v4 执行流程，沿用 [重建基础协议](RECONSTRUCTION_V3.md) 的原件登记、完整画幅智能对象放置与原生文字实测，增加元素归属及最终合成审查。旧案例的完成状态保留，不自动重做。

## 你会看到什么

1. Codex 按已有建议分层、画幅、意见和标注制定逐层做法。位图通常生成素材后在 PS 合成；文字与形状依据实际参考选择方法。原生文字要匹配真实字形，简单字行也不能默认套用字体。依据实际尝试仍不能匹配时改成独立像素层，并标明不可编辑。
2. 先设计合成方式再生图：透明或黑底、混合模式、蒙版、遮挡，以及哪些效果交给 PS。背景会去除已经拆出来的内容，防止重复文字或光效。
3. 位图素材不足目标尺寸时，在同一任务内自动使用 SeedVR2，再等比放回对应画幅。原文件一直保留；超分破坏细节或不可用时可以退回等比缩放。原生文字、矢量和 PS 效果直接在目标尺寸制作。
4. 保存后由 PS 重新打开副本、渲染完整图及各组预览。Codex 查看实际文件，按层改进，再检查合成。有明显问题但已尝试修复的层标红、写入修改意见；其余层标记保留。问题层不会卡住所有已经完成的层。

所有建议层都必须映射到真实 PS 分组，不能以整图垫底加占位层冒充完成。结构检查和视觉检查分开：结构检查能发现漏层、空层、隐藏占位、假称可编辑等问题；视觉是否一致仍需查看真实结果，不能保证任意复杂设计完全还原。

## 物体分层与文字匹配

局部裁片只用于参考，不能直接当最终图层。位图默认由当前对话实际生图；允许的提取路线须沿物体轮廓形成透明区域，补全遮挡。人物不能混入背景、产品或其他卡片；背景不能用模糊人物、文字残影替代补全。原生文字须实际可见并承担最终文字外观，不以隐藏的普通文字备份假称已重建。

插件在素材注册时检查实际alpha和参考裁片副本，再处理超分。在PS重新打开后还检查图层框内的透明区域，避免矩形裁片外面加透明画布绕过检查。PS会导出逐层浅底、深底和透明预览，Codex必须逐层查看对象归属、边缘、补全和实际合成。

普通完整不透明背景置入 PS 时，短边向外覆盖1像素，长边按相同比例扩展，并记录实际变换，避免智能对象重采样在文档外周产生半透明缝。已登记的source-protected保护背景则须同尺寸满幅1:1置入，不能用扩边放大改变受保护位置；置入和最终检查逐一核验四角。四角正确仍须检查实际PS导出的像素、颜色及边缘。普通防空边处理不适用于前景，也不会填补素材内部的透明空洞；内部缺失仍会拒绝验收。

原生文字的 `textTargets.box` 必须按源图实际字形墨迹确定，不能把带留白的分层 `frame` 或生成 carrier 整框直接当拟合目标。插件改进循环在新计划冻结前，先查看同源原尺寸字行，分别记录墨迹范围、字体粗细和内部字距，并独立读回确认；颜色阈值得到的边界仅是观察辅助，不能自动确认文字语义。源墨迹不能确认时，保留限制，不用猜测整框替代。旧冻结目标和失败试排保留，事后诊断不得追改目标或伪装为事前证据。

`fit-text` 根据PS实测字形边界向已确认的源墨迹框调整位置、等比大小、字距、颜色及变形。默认不会分别拉伸宽高；支持目标旋转、斜切、弧形等文字变形、描边和投影。拟合只是辅助：字体、透视、渐变等仍需实际制作和叠图复核。字体未确认时先读取实际安装字体，按同源单字宽度、笔画和字符位置选择有限候选，新诊断一次最多比较三个有依据的字体，不预设统一字体或字距。诊断副本与冻结计划区别记录；改变已冻结字体或路线时另存新计划修订，绑定同一task/job/layer、原计划摘要和修改原因，保留旧计划和源点。参数改变不能冒充原计划匹配。依据实际失败评估独立像素层并标明不可编辑，简单字行也适用。尚未解决的字行标为需修订，继续其他独立层和可验证关系。

生成记录保存实际提示词、允许参考的摘要、返回素材及尝试文件；不能只填写“generated”。这些记录提供追溯，不等于后台可独立证明宿主调用了某个内部模型。图像语义归属和艺术字视觉匹配仍由Codex查看真实结果判断，程序检查不能保证任意素材完美分层。

旧版已完成结果保持不变；未完成任务按冻结的协议版本兼容，新任务使用v4执行流程，不自动重做历史。明显漂移经过不同方法尝试后仍可红标继续；无效裁片、空层和缺文件不能标成完成。

高保真优先时，PS 可选路线可真正提取原图可见物体，以生成素材补全遮挡；预分层抠图依旧只供规划。提取须保留合理的软透明边缘，不能硬阈值锯齿、混入背景或假称可编辑文本。保护背景可见区域时，先去掉所有已拆出的前景，缺失处才使用生成背景。文字审查比较实际笔画、内部字距、颜色及变形，不能只以文字边界框吻合判定通过。

光效需在最终叠加中检查星心、细线和大范围柔散射是否真的保留；层顺序、蒙版和混合方式都会影响结果。前景桌面等遮挡人物的物体在规划时应独立列层，不能与最底背景混为一层。以上是 Codex 的执行与审查策略，尚不代表插件具备通用自动抠图、字体匹配或光效逆向拟合功能；具体海报脚本只作为该案例证据。

## 设置

设置 → PS / AI → PS 重建：

| 设置 | 默认 | 用途 |
|---|---|---|
| 允许从原图准确提取 | 开 | 可以从干净原图提取适合的元素，再补全遮挡。预分层抠图像素仍不允许用作最终素材。 |
| 像素不足自动超分 | 开 | 素材需放大超过1.15倍时使用本地 SeedVR2；不超过1.15倍使用等比插值，避免150万预算造成的轻微缩小触发耗时超分。参数沿用超分页，不消耗 Codex 额度。 |
| 每层最多尝试 | 3 次 | 包含首轮；更多尝试增加时间和 Codex 额度。仍不理想时标红保留结果。 |
| 生图请求/工作预算 | 固定 150 万像素 | 普通与PS统一，包含透明留白；实际超预算返回另存原件和等比工作副本，不是对工具内部尺寸参数的声明。 |

保存后同时用于当前画布后续任务和新画布。正在执行的任务仍使用提交时冻结的参数。

需要明确强制测试小幅超分时，执行接口支持 `upscale-material` 的 `force:true`；仍须先检查真实PS合成，不能改写保留层。默认不强制，不新增设计师操作步骤。

## 原生结果如何使用

- 画布显示 **PS 实际渲染图**，不使用简化网页图层合成模拟特殊样式。图层栏保留逻辑分层，每层可对应多个 PS 子层。
- 显隐、透明度和排序会在 PS 副本上更新并重新渲染；PS不可用时保存失败并保留上一版，不假装已经生效。标注、意见和节点位置仍可照常编辑。
- “提交 PS 修改”继续走原生流程，保留未修改组。PSD 导出保留原生结构、变形、混合与样式；PNG 导出使用最近成功的真实合成。
- 局部PS修改需要其他层已完成。其他层仍是建议框／抠图预览时，请取消图层选择后交接整张图；插件不会擅自把局部任务扩大成全图重建。
- 本版原生渲染校验依赖 Windows 的 PS 脚本通道。MCP 可以用于重建操作，但仅 MCP 连接成功不足以替代渲染检查。
- 此类复杂原生 PS 节点暂不使用顶部普通逐层超分，以免丢失原生效果。要更大的 PSD，可在总图意见中写明等比目标尺寸，再交接 PS；素材自动超分发生在装入 PS 前。

不覆盖已打开的用户文档，不静默调用 Adobe/Firefly 收费生成功能。当前会话尚未发现新 MCP 工具时，智能体可用项目 CLI 调用同一接口，无需用户手动接单。

## 开发与验收

核心实现：`shared/photoshop.ts`、`server/photoshop-rebuild.ts`、`server/photoshop-native.ts`。执行契约见插件技能目录的 `PHOTOSHOP.md`；API是当前任务绑定的 `canvas_ps_rebuild` / `/api/jobs/:id/ps-rebuild`。

逐层计划、素材原文件、超分候选、实际PSD副本和审查状态保存在本任务目录；重复相同计划保留材料，变化使相关材料或旧检查失效。最终回传必须使用最后检查的未变更PSD。素材来源描述及视觉报告由执行智能体负责，不能只凭文件推断调用了哪个生图模型。

独立视觉审查使用不可变序号或唯一文件路径，并记录SHA256与对应的逐层透明、深浅底预览；评审期间不覆盖候选。尚未通过的视觉候选保留“待审查/需修正”状态，不以接口成功或结构通过宣称全部图层一致。

已做隔离样例的真实 Photoshop 往返检查：原生弧形文字、合成逐像素比对、显隐恢复、关联新节点、保护已有文档。这个测试验证技术流程，不代表复杂海报的生成重建效果已验收。SeedVR2 素材集成另有尺寸、alpha、失败回退测试。


## 原生连续薄膜（C63，制作入口与工程验证）

PS新v4 native/shape/native-shape透明thin-film分件可冻结nativeFilm:{version:1,observation,knots,gradient:{angle,stops}}。闭合Bezier每结点为最终PS画布像素[inX,inY,anchorX,anchorY,outX,outY]，3–64点，锚点/控制点在冻结frame内。渐变2–8色标，position严格递增且端点0/1，color为整数RGB，alpha为1..254，angle为-180..180度。配方只记录事前人工观察和明确制作参数，不从源裁片取像素、不推断物理透射率；印字/实边与水滴等其他分件继续按C62排除。无配方的native thin-film声明不能当已实现制作。

canvas_ps_rebuild input:{action:"render-native-film",layerId,inputPsdPath}只接受本job PSD，完整工作画布含留白<=150万像素，目标LC组必须空。创建真正带可编辑vectorMask/原生渐变填充的独立源PSD，再由已配置AdobeConnector.executeScript让实际PS把形状置入输入的新副本并保存。原输入、其他组和用户已打开文档保留；对话task/job不符、非空目标或超预算在执行前拒绝。状态记录nativeFilms制作回执但不写accepted；冻结完整计划，重放仅在计划、输入、实际输出摘要未变时复用原回执，避免重复原生制作。

实际保存后的路径锚点/控制点（0.01像素序列化容差）、渐变颜色、透明度色标/位置、正常混合及唯一内容均回读校验；inspect-progress和最终PSD结构检查再次核验原生组，不能用隐藏层、位图、额外印字、挖孔路径或修改配方后文件冒充。仍必须inspect真实PS透明组PNG的clear/transmissive规则、深浅底和原图外观；工程PSD缓存与模拟脚本不证明PS设备行为或视觉一致性。普通路线继续自己的真实image_gen，不把原生薄膜输出冒充image_gen。

C63已通过工程结构/接口及模拟Adobe执行测试；其“模拟”不是实际PS回执。下一次R43必须新复杂源，源冻结后事前观察填写配方，执行真实Photoshop制作/渲染并对照，普通单独真实生成。两路线完整海报输出与独立审查尚未验收。
# C69：显式原生平面文字

C71新增本job内 `text-plane-progress-*.json` 实际脚本阶段记录：打开新副本、创建文字层、设字体、变换及保存前写入阶段。PS/COM异常后先查看此文件与实际输出，不能盲目重复调用或强制关闭用户文档。阶段文件是定位线索，不是成功或验收证明。

冻结PS层可选 `nativeTextPlane:{version:1,recipe:<nativeText v2>}`。配方与普通路线共用真实字体文件摘要、字号、颜色和六参数平面；PS `textTargets` 同序记录行名、文字、观察墨迹框与外观。仅透明 native/text/native-text 可用，光学印字限 v2 opaque-structure；薄膜、光效、位图、fallback 和源保护不能混用。

`render-native-plane-text` 接收本job `inputPsdPath` 和 `layerId`，目标组必须空、画布须与冻结计划一致且含留白不超过150万像素、PS工作分辨率72dpi。先核对真实TTF/OTF摘要及PostScript名、字形覆盖与观察框，再在新PSD副本中按分解后的缩放/斜切/旋转制作原生文字。缩放来自事前平面，不按成品包围盒拉伸；平移只定位事前观察墨迹左上角。用户原文档及原输入保留。

制作后及进度/最终结构检查均回读实际PSD原生字体、字号、颜色、变换、可见性、位置和逐行内容；不接受隐藏/像素占位、额外层、样式替换或事后fit-text。完整计划在首次prepare或原生制作后冻结；收据仅在计划、字体文件、输入及实际输出未变时复用。单行字段不一致或任务状态竞争会保留新文件而拒绝提交。

回执只证明原生制作与结构回读；仍须实际PS导出alpha/深浅底、源字形外观和整图独立审查。C68的实验脚本不等于此接口已经在新复杂源上验证，代码测试中的Adobe模拟也不等于真实PS运行。

C72区分原图观察框与真实字体墨迹：原生制作保持冻结字体、字号和完整平面，左上定位仍按1.1像素检查；墨迹尺寸按实际字体度量与冻结平面检查，允许两种渲染引擎及整数栅格边界最多2像素差异，超出则拒绝。保存的PS文字局部边界还须与实际基线变换一致，墨迹不得越出冻结画幅。不会将原图框宽高用作拉伸目标。回读返回逐行原图尺寸差异及`sourceVisualAccepted:false`，即使制作正确也不自动接受源字体或字形一致性；倾斜较大时字形极值可能达不到度量矩形角点，仍可能需要诊断，不能放宽门槛冒称通过。
